## R1. 数据源维护保存错误修复

### 1.1 问题描述

在数据源维护功能中，用户再次保存数据源时出现数据库原始错误：`UNIQUE constraint failed: data_sources.projectId`。

**根因分析**（基于代码审查）：

- `data_sources` 表定义了 `projectId TEXT NOT NULL UNIQUE` 约束，即每个项目只能有一个数据源
- 前端 `projectStore.createOrUpdateDataSource()` 已实现"先查后决定创建/更新"的逻辑
- 但 `DataSources.tsx` 的 `handleSaveDs()` 中 `catch` 块仅 `console.error`，未向用户展示任何错误信息
- 当应用层逻辑因并发、状态不同步等原因未能正确判断"创建还是更新"时，数据库原始错误直接抛出

### 1.2 产品需求

#### 1.2.1 错误友好化处理

- 当保存数据源失败时，**禁止展示数据库原始错误信息**（如 `UNIQUE constraint failed`）
- 根据错误类型，展示用户可理解的友好提示：
  - 唯一约束冲突 → "该项目已存在数据源配置，请使用编辑功能修改"
  - 连接失败 → "数据库连接失败，请检查配置信息"
  - 其他错误 → "保存失败，请重试。如问题持续，请联系技术支持"
- 错误提示使用页面内 Toast 或 Alert 组件展示，**不使用 `alert()` 弹窗**

#### 1.2.2 新建与编辑场景明确区分

当前代码中"新建数据源"和"编辑数据源"共用同一个弹窗和保存逻辑，用户无法感知当前是哪种操作。需要：

- **弹窗标题区分**：新建时显示"配置数据源"，编辑时显示"编辑数据源"
- **保存按钮文案区分**：新建时显示"保存"，编辑时显示"更新"
- **编辑时自动回填**：编辑时表单自动填充已有数据源的所有字段（当前已实现，需确保密码字段也能正确回填）
- **编辑时锁定关键字段**：编辑模式下，数据库类型字段不可修改（因为不同数据库类型的连接参数不同，修改类型可能导致连接信息不兼容）

#### 1.2.3 保存前校验增强

在用户点击保存按钮后、实际提交前，进行以下校验：

| 校验项 | 规则 | 提示方式 |
|--------|------|---------|
| 必填字段 | 数据源名称、主机地址、端口、用户名、密码不能为空 | 字段下方红色提示文字 |
| 端口范围 | 端口号 1-65535 | 字段下方红色提示文字 |
| Oracle 连接参数 | SID 和 Service Name 至少填一个 | 字段下方红色提示文字 |
| 达梦连接参数 | 数据库名称必填 | 字段下方红色提示文字 |
| 连接测试 | 保存前自动测试连接，失败时提示"连接测试未通过，是否仍要保存？" | 确认弹窗（可选继续保存） |

#### 1.2.4 保存成功反馈

- 保存成功后，弹窗自动关闭
- 页面顶部显示绿色 Toast 提示"数据源保存成功"（新建）或"数据源更新成功"（编辑）
- Toast 3秒后自动消失

### 1.3 验收标准

1. 新建数据源：填写完整信息 → 保存成功 → Toast 提示 → 弹窗关闭 → 数据源信息展示
2. 编辑数据源：点击编辑 → 表单回填 → 修改信息 → 更新成功 → Toast 提示 → 弹窗关闭
3. 重复保存：无论何种场景，不再出现 `UNIQUE constraint failed` 原始错误
4. 校验不通过：必填字段为空时，保存按钮禁用或点击后显示校验提示
5. 连接测试失败：提示用户，允许选择继续保存或取消

## R2. 条件查询与排序条件布局优化

### 2.1 问题描述

条件查询和排序条件区域的宽度跟随表格宽度变化，导致以下体验问题：

- 表格列数较多、水平滚动时，条件区域被挤压或偏移
- 条件区域与表格区域在视觉上没有清晰分层
- 窗口大小变化时，条件区域布局不稳定

**当前代码结构**（基于代码审查）：

```
查询面板 (flex-col overflow-y-auto, 全局滚动)
├── 工具栏 (border-b, 渐变背景)
├── 条件区域 (flex-row, 左63% + 右37%)
│   ├── 左栏 - 查询条件 (md:w-[63%])
│   ├── 分隔线
│   └── 右栏 - 排序条件 (md:w-[37%])
├── 查询结果表格 (overflow-x-auto, sticky thead)
└── 回到顶部按钮
```

整个查询面板是一个统一的滚动容器，条件区域和表格在同一个 flex 列中，表格的 `overflow-x-auto` 可能影响上方条件区域的布局计算。

### 2.2 产品需求

#### 2.2.1 条件区域布局固定

- 条件查询和排序条件区域的宽度**始终与窗口/容器可用宽度一致**
- 无论表格如何水平滚动或调整列宽，条件区域的位置和宽度保持不变
- 条件区域始终位于表格上方，占据完整的可用宽度

#### 2.2.2 表格独立滚动

- 表格区域拥有独立的水平滚动能力
- 表格左右拖动/滚动时，**仅表格内容区域滚动**，条件查询区域保持固定
- 条件区域与表格区域之间有明确的视觉分隔线

#### 2.2.3 响应式适配

- 窗口大小变化时，条件区域自动调整宽度以适配新的窗口尺寸
- 条件区域内部的查询条件和排序条件元素在宽度变化时合理布局：
  - 宽屏：左右两栏（查询条件 63% + 排序条件 37%）
  - 窄屏：上下堆叠（查询条件在上，排序条件在下）
- 表格列宽在窄屏下自动压缩或提供水平滚动

#### 2.2.4 条件区域折叠（补充优化）

- 当条件区域占用过多纵向空间时，用户可点击折叠按钮收起条件区域
- 折叠后仅显示标题栏（"查询条件 (3项) | 排序条件 (2项)"），点击可展开
- 折叠状态在当前会话内保持

### 2.3 验收标准

1. 条件区域宽度始终与窗口一致，不随表格水平滚动而变化
2. 表格水平滚动时，条件区域位置固定不动
3. 窄屏下条件区域自动切换为上下堆叠布局
4. 折叠/展开功能正常，折叠后条件区域仅显示一行摘要
5. 窗口缩放时，条件区域平滑自适应

## R3. AI报表模块交互体验优化

### 3.1 问题描述

AI报表模块已有基本功能（自然语言→SQL→图表），但交互体验粗糙，主要体现在：

- 发送按钮样式简陋，无加载动画，生成中仅显示"..."文字
- 输入区域功能单一，缺少清空、字数提示等辅助功能
- 对话区域缺少复制、重新生成等常用操作
- 整体交互缺乏状态反馈

**当前代码状态**（基于代码审查）：

- 发送按钮：`<button className="px-4 bg-blue-500 text-white rounded-lg ...">{isGenerating ? '...' : '发送'}</button>`
- 输入框：`<textarea rows={2}>`，无自动高度调整
- AI消息：Markdown 渲染已有，但缺少复制按钮
- 流式响应：已实现 chunk 追加，但无"正在输入"指示器

### 3.2 产品需求

#### 3.2.1 发送按钮优化

**视觉设计**：

| 状态 | 视觉表现 |
|------|---------|
| 默认（可发送） | 蓝色实心按钮，右侧带发送图标（→ 或纸飞机），文字"发送" |
| 禁用（空内容/生成中） | 灰色按钮，`opacity-40`，不可点击 |
| 加载中（AI生成中） | 按钮内显示旋转加载动画（spinner），文字变为"生成中..."，按钮禁用防止重复提交 |
| 悬停 | 蓝色加深，轻微上浮阴影 |

**交互行为**：

- Enter 键发送（已实现，保持）
- Shift+Enter 换行（已实现，保持）
- 生成中禁止重复发送（已实现，保持）
- 生成完成后，输入框自动聚焦，方便继续输入

#### 3.2.2 输入区域优化

| 优化项 | 说明 |
|--------|------|
| 自动高度 | 输入框根据内容自动调整高度，最小2行，最大6行，超出后内部滚动 |
| 清空按钮 | 输入框右侧（发送按钮左侧）显示清空图标按钮（×），点击清空输入内容；输入框为空时隐藏 |
| 占位提示 | 优化 placeholder 文案："描述你想查询的数据，例如：本月门诊收入趋势" |
| 字数提示 | 输入框右下角显示当前字数，超过2000字时变红提示 |
| 文件附件标识 | 拖入文件后，在输入框上方显示附件标签（文件名 + 文件大小），可点击 × 移除（已实现，优化样式） |

#### 3.2.3 对话区域优化

**AI消息操作栏**：

每条AI回复消息底部，提供以下操作按钮（图标+文字，水平排列）：

| 按钮 | 功能 | 显示条件 |
|------|------|---------|
| 📋 复制 | 复制AI回复的完整文本内容到剪贴板 | 始终显示 |
| 🔄 重新生成 | 基于相同的用户输入重新调用AI生成 | 仅最新一条AI消息显示 |
| 🗑️ 删除 | 删除该条AI回复及其对应的用户提问 | 始终显示 |

- 复制成功后，按钮文字临时变为"已复制 ✓"，2秒后恢复
- 重新生成时，替换当前AI消息内容（非新增一条）

**AI正在输入指示器**：

- AI开始生成回复时，在AI消息气泡内显示"思考中..."动画（三个点依次跳动）
- 流式内容到达后，替换为实际内容
- 如果AI回复为空且已结束，显示"AI未返回有效内容，请重试"

**用户消息操作**：

- 用户消息气泡暂不提供操作按钮（保持简洁）
- 用户消息与AI消息之间有清晰的视觉区分（颜色、对齐方式，当前已实现）

#### 3.2.4 整体布局优化

| 优化项 | 说明 |
|--------|------|
| 对话区域滚动 | 对话区域独立滚动，新消息自动滚到底部（已实现，保持） |
| 输入区域固定 | 输入区域固定在底部，不随对话滚动（已实现，保持） |
| 空状态引导 | 对话为空时，显示引导提示："👋 你好！我是AI报表助手，告诉我你想查询什么数据" |
| 消息时间戳 | 每条消息下方显示发送时间（如"14:30"），灰色小字 |
| 长消息折叠 | AI回复超过500字时，默认折叠显示前200字 + "展开全部"按钮，点击展开 |

### 3.3 验收标准

1. 发送按钮四种状态（默认/禁用/加载中/悬停）视觉正确
2. 加载中显示旋转动画，按钮禁用不可点击
3. 输入框自动调整高度，最小2行最大6行
4. 清空按钮在有内容时显示，点击后清空输入
5. AI消息底部操作栏（复制/重新生成/删除）功能正常
6. 复制成功后按钮临时变为"已复制 ✓"
7. AI生成中显示"思考中..."动画
8. 对话为空时显示引导提示
9. 每条消息下方显示时间戳
