- **行为**：流式输出事件增加 `requestId`，渲染端只接收当前助手消息对应的流，避免旧请求片段串到新消息。

### 七、关系规划与种子发布（2026-05-22 补充）

#### 1. 关系规划（阶段5 轻量落地）

- **文件**：`main/report/relationPlanner.ts`、`main/report/joinExtractor.ts`、`main/report/reportSession.ts`
- **行为**：
  - SQL 正式生成前，先让模型输出关联计划 JSON（neededTables + joins）
  - 对计划中的新关系仅做 `validateJoin` 语法验证，**不立即写入缓存**
  - 以 `【本轮候选关联】` 注入 Prompt，已持久化关系以 `【强制可用关联】` 注入
  - **查询有数据后才保存**：AI 试执行或用户点击「执行 SQL」返回 `rowCount > 0` 时，从实际 SQL 的 ON 子句提取 JOIN 并写入 `table_relationships`
- **价值**：避免 AI 推理出的错误关联被提前固化；只有真实跑通且有结果的 SQL 才沉淀为关系

#### 2. 语义学习数据随安装包发布

- **文件**：`main/database/portableSeed.ts`、`scripts/exportPortableSeed.ts`
- **行为**：
  - 导出种子时新增 `tableRelationships` 与 `semanticFieldLearning`
  - 应用首次导入便携种子时同步导入以上数据
- **效果**：发布包可携带训练好的关系与语义学习成果，安装后即生效

#### 3. 种子发布前校验（新增）

- **文件**：`scripts/verifyPortableSeed.ts`、`package.json`
- **行为**：

  - `dist` 流程改为 `seed:heat-init -> seed:export -> seed:verify -> build -> electron-builder`

#### 4. 业务规则初始化表热度（新增）

- **文件**：`resources/constraints/business-rules.md`、`main/report/businessRulesHeat.ts`、`scripts/initTableHeatFromBusinessRules.ts`
- **行为**：
  - 从 ZOEHIS 业务规则文档解析 `PAT_`/`CHA_`/`PRES_` 等表名
  - 门诊/住院业务流程章节权重更高（5），完整表清单次之（3）
  - 按 Schema 缓存匹配 `OWNER.TABLE` 真实表名，写入 `table_heat.manualWeight`
  - 不覆盖已有更高的 manualWeight，不影响 queryCount/reportCount
- **命令**：`npm run seed:heat-init`（支持 `--dry-run`、`--rules <path>`）
