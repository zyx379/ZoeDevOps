需求：

1、如果数据查询的时候表的字段很多，那么查询条件和排序条件会被拉长，不便于操作，希望得到改善。

2、我希望有一部分数据可以另一种形式存储，达到的效果是在打包或者提交代码后，切换到另一台电脑启动程序仍然能够被携带。希望达到此类效果的数据：项目配置内容、表结构。

3、目前报表功能难用，匹配不精准。希望增加合理的机制，以下是我想到的方向，如果有更好的办法可以补充：

（1）表热度评分机制：数据查询的使用、报表的采纳、都可以增加一张表的热度，优先匹配热度高的表。

（2）不确定用哪张表的时候，是否可以让用户主动选择。AI初步筛选后，让用户选择此次报表明确要用的表。

（3）此类数据也存到第二点提出的“特殊存储”，并且有界面可以查看以及删除、清空


实现记录：

1、数据查询页优化：
- 查询条件、排序条件继续使用原有 SQL 生成逻辑。
- 添加字段下拉改为 React 状态驱动筛选，避免依赖当前焦点元素导致宽表字段筛选不稳定。
- 条件区进一步压缩高度，降低条件/排序较多时对结果区的挤占。

2、安装包内置种子数据：
- 新增 `resources/seed/portable-seed.json` 作为打包携带的种子数据文件。
- 新增 `npm run seed:export`，从当前本机 userData 中导出项目、数据源、项目配置、表结构缓存、表热度。
- 程序启动初始化数据库后会自动导入安装包中的种子数据，并通过 `seed_imports` 记录避免重复覆盖。
- 敏感字段按当前本地数据库中的加密值导出，随安装包携带。

3、表热度评分：
- 新增 `table_heat` 存储，记录查询次数、报表次数、手动权重、最近使用时间。
- 数据查询执行成功后增加查询热度；AI 报表 SQL 执行成功后增加报表热度。
- AI Schema 匹配在关键词得分相同或无关键词时优先选择热度更高的表。

4、报表选表：
- 报表页左侧新增“表”页签，可搜索表结构、查看热度、勾选本次报表使用的表。
- 用户勾选表后，AI prompt 会限制本次报表优先且仅使用这些表。
- 支持删除单表热度、清空当前数据源热度。
